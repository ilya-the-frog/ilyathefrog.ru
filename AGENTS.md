# Инструкция для AI-агентов

Личная визитка [ilyathefrog.ru](https://ilyathefrog.ru/): статический сайт на HTML, CSS и JavaScript без сборки, фреймворков и зависимостей. Всё, что попадает в `main`, автоматически деплоится в веб-рут на Beget, поэтому файлы репозитория (включая этот) публично доступны на сайте.

## Карта проекта

- `home.html` — единственная страница: структура, SEO-мета, Open Graph и контентные блоки.
- `index.md` — Markdown-версия главной для агентов, на английском.
- `js.js` — словарь переводов `translations` (ru/en), переключатель языка, автоформат дат публикаций.
- `index.php` — front controller: отдаёт `index.md` при `Accept: text/markdown`, иначе `home.html`; выставляет `Link`-заголовки и `x-markdown-tokens`.
- `llms.txt` — карточка сайта для LLM, на английском.
- `style.css`, `normalize.css` — стили; фавиконки и web manifest — визуальные ассеты.
- `.htaccess` — content negotiation и заголовки для Apache/Beget (локально не исполняется).
- `robots.txt`, `sitemap.xml` — служебные файлы для поисковиков.

## Главный инвариант: контент живёт в четырёх местах

Любое контентное изменение (публикация, выступление, текст о себе) вносится согласованно:

1. `home.html` — разметка. Статический текст в HTML — русская версия (fallback), у каждого текстового узла атрибут `data-i18n="<ключ>"`.
2. `js.js` — ключ добавляется в **оба** словаря: `translations.ru` и `translations.en`.
3. `index.md` — английская Markdown-версия того же контента.
4. `llms.txt` — соответствующий раздел: `## Important Pages` для публикаций, `## Speaking` для выступлений.

Если после изменения при переключении на EN текст остаётся русским — ключа нет в `translations.en`.

## Рецепты

### Добавить публикацию

- `home.html`: `<li class="links__link" data-pub-date="YYYY-MM-DD">` **первым** в списке секции `PUBLICATIONS` (сортировка от новых к старым). Внутри: `<p class="links__title" data-i18n="publications.<slug>.publisher">`, ссылка с `data-i18n="publications.<slug>"` и пустой `<span class="links__date"></span>` — дата подставляется скриптом из `data-pub-date`, вручную её писать не нужно.
- `js.js`: ключи `publications.<slug>.publisher` и `publications.<slug>` в ru- и en-словари.
- `index.md`: строка `- YYYY-MM-DD, Publisher: [Title](URL)` первой в разделе `## Publications`.
- `llms.txt`: строка `- Publisher - Title: URL` в `## Important Pages` сразу после Home и Sitemap (новые выше).

### Добавить выступление

- `home.html`: `<li class="links__link">` в **конец** секции `SPEAKER`, ключи `speaker.<slug>.title` и `speaker.<slug>.link`.
- `js.js`: оба словаря; текст ссылки обычно «Выступление» / "Talk". Если есть запись, вместо этого отдельные ссылки на площадки (YouTube, VK Видео).
- `index.md`: строка в конец раздела `## Speaker`.
- `llms.txt`: строка в конец раздела `## Speaking`.

## Языки

- Русский — основной язык контента, английский — обязательный перевод всего видимого пользователю.
- Названия брендов: если у медиа есть английское имя, в en-словаре используется оно («Код» → "The Code"); латинские бренды (ComNews, KP.RU, Habr → Хабр/Habr) остаются как принято у самого бренда.

## Проверка

- Открыть `home.html` в браузере — основная визуальная проверка. Обязательно проверить переключатель RU/EN на новом контенте.
- Поведение `/` и Markdown-ответ:

  ```sh
  php -S 127.0.0.1:8787
  curl -i http://127.0.0.1:8787/ -H 'Accept: text/markdown'
  ```

- `.htaccess`-правила и серверные заголовки проверяются только на проде (подробности в README).

## О чём легко забыть

- `sitemap.xml`: обновить `<lastmod>` при контентных изменениях.
- `index.php`: `x-markdown-tokens` — примерная оценка размера `index.md` в токенах; при заметном изменении файла пересчитать (≈ количество символов / 4).

## Git

- Пуш в `main` — это деплой на прод. Не коммитить и не пушить без явной просьбы владельца.
- Сообщения коммитов — краткие, на английском, в духе `Add new Habr publication`.
